# REA 差异分析与网页改造交接

**基线** `3f4a0bb98901e2b48dcf7721202e94af8a4fa4cc`。本文记录 APK 静态证据、网页实测结果，以及可独立实施的网页改造方案。交付目标是在现有叠层三消玩法上做出有原创棋盘、界面和素材的可玩网页游戏。先修通关和裁切，再做状态一致性与界面。

### 旧资源表可回答的问题

`resources/config.json` 有 23,045 条带类型的记录和 12,666 个不同逻辑路径。其中 10,113 个路径对应多条记录。资源目录内有 23,321 个 `import` 成员和 10,631 个 `native` 成员。旧表有 12,666 个键，2,273 条的 `file` 为 `null`。旧脚本优先查指定后缀的 `native` 文件，按逻辑路径存一个结果，因此会合并同路径下的 `SpriteFrame`、`Texture2D` 等记录。`file: null` 只说明该查找规则未匹配。场景和 Prefab 的节点、引用及排布属于另一层序列化数据，图片清单本身不足以解释画面差异。[旧映射脚本](tools/uuid_map.js)

## 2. 已确认的网页差异

| 问题 | 基线表现 | 实现入口 |
| --- | --- | --- |
| 棋盘形状 | 网页以少量固定矩形层生成 42 块和 120 块，截掉不足三张的尾部。参考截图可见上下两组牌阵、中部区域与两侧牌堆。 | `buildLevel()`、`boardXY()` |
| 棋盘裁切 | 在 594×1320 视口中，舞台可见横向边界约为 3.12–590.88 像素。第一关 7 块、第二关 30 块至少部分越过边界。第二关未裁切的棋盘横向范围约为 -9.87–758.23 像素。 | `#viewport`、`#stage`、`#board`、`fitStage()` |
| 数量与通关 | 第一关类型 1、2 各 6 张，其余 6 种各 5 张。第二关 12 种各 10 张。每次消除扣减某类型 3 张，移出、撤回与洗牌保持类型总数，胜利要求三个区域清空。两关均无法正常通关。 | `buildLevel()`、`checkCrush()`、`checkWin()` |
| 视觉和状态 | 网页背景、托盘用 CSS 渐变，道具使用内联 SVG 和剩余次数。参考截图显示草地插画、围栏托盘、带描边图标、签到浮层和加号徽标。更换贴图无法修复关卡数据与布局错误。 | `#hud`、`#propsBar`、`#slotTray` |
| 操作状态 | 源码有两个 `onReleaseBlock()` 声明。入槽会重置暂存来源，撤回统一把块推回棋盘。`mountMoveout()` 同时设置属性事件，而棋盘已通过 `addEventListener` 注册。槽位有效数按滑动窗口减三，四张同类相邻时会重复扣减。异步结算和重开交错的表现需用回归测试确认。 | `pickBlock()`、`mountMoveout()`、`useUndo()`、`effectiveSlotCount()`、`startLevel()` |

### 本地复测

在基线提交执行 `python3 -m http.server 8080 --directory public`。打开 `http://127.0.0.1:8080` 并点击开始，在 DevTools 设备模式设 **594×1320 CSS 像素**、100% 页面缩放。以下控制台命令复测开局类型计数与舞台左右裁切。它以牌的完整边框计算裁切，故意保留了牌间遮挡。

```js
Array.from([0, 1], (level) => {
  gotoLevel(level);
  const tiles = [...document.querySelectorAll('#board .block')];
  tiles.forEach((tile) => tile.classList.remove('enter'));
  const stage = document.querySelector('#stage').getBoundingClientRect();
  return {
    level: level + 1,
    viewport: [innerWidth, innerHeight],
    count: tiles.length,
    types: buildLevel(level).reduce((counts, { type }) => {
      counts[type] = (counts[type] ?? 0) + 1;
      return counts;
    }, {}),
    clipped: tiles.filter((tile) => {
      const rect = tile.getBoundingClientRect();
      return rect.left < stage.left - 0.01 || rect.right > stage.right + 0.01;
    }).length,
  };
});
```

## 3. 实施顺序

以下是实现决策。用本地关卡数据、静态资源和浏览器入口保持项目可离线开发。关卡和规则可用 Node 内置测试运行器检验。涉及布局、焦点、指针输入和动画的验收在浏览器中执行。

### P0 · 关卡数据与可解性

- [ ] 把 `buildLevel(levelIdx)` 的数据生成与 `startLevel()` 的 DOM 启动分开。可新建 `public/levels.mjs`，导出 `buildLevel(levelIdx)`。每张牌含稳定 ID、类型、层和逻辑坐标。为两个关卡分别设计原创拓扑和固定种子。
- [ ] 在 `tests/levels.test.mjs` 断言稳定输入生成相同牌阵、ID 唯一、位置有限且无同层重复、类型数量逐一为 3 的倍数。运行 `node --test tests/levels.test.mjs`。
- [ ] 每关随测试保留一组合法的点击顺序。按同一套遮挡与槽位规则逐手回放，覆盖从初始状态到胜利。制作牌阵时可先选择合法的移除次序，再按三张成组安排类型。若允许随机种子，生成器也要给出能复验的解，或者限制发布的种子为已有解的集合。
- [ ] 从网页首页正常开始，完成第一关、进入第二关并结算。对照测试顺序检查整个过程能够在用户操作入口完成。

### P0 · 统一棋盘、槽位和道具的布局

- [ ] 在 `public/index.html` 更新 `fitStage()` 和 CSS。将页头、棋盘、暂存、槽位及操作区放进明确的响应式区域。背景可铺满窗口，棋盘按自身包围盒完整缩放。把牌的宽高及层间偏移计入包围盒，缩放后再在实际可用区域内居中。
- [ ] 让棋盘、槽位和暂存区各自从容器坐标计算牌位。`boardXY()`、`layoutSlot()` 和移动动画使用同一个坐标转换，去掉为跨区飞行硬编码的纵向偏移。窗口改变时只重算布局，保留对局状态。
- [ ] 在 360×800、390×844、594×1320、768×1024 和 1280×800 验收两关。牌边框都落在棋盘容器内，允许牌之间按规则遮挡。七格槽位、暂存顶牌、道具与退出入口在各自区域可操作。加测移动浏览器安全区、旋转和键盘焦点。

### P1 · 对局状态与道具

- [ ] 让一次用户动作只经过一个处理入口。用牌 ID 和来源描述移动，在棋盘、槽位、暂存及已消除集合之间维持唯一归属。暂存堆只接受顶牌回槽，撤回时恢复原区域和相对位置。
- [ ] 把入槽、三连结算、槽满和胜利条件置于单一顺序。连续同类只匹配互不重叠的三张。`AAAA` 只能消一组，`AAAAAA` 可消两组。把动画作为状态变化后的呈现，用本局标识或取消机制隔离重开、退出和换关后迟到的回调。
- [ ] 对无效操作保留道具次数。洗牌仅重排仍在棋盘上的牌。移出、撤回和复活分别在成功之后扣减或记录使用状态。把复活次数、道具重置规则作为网页产品决策写入测试，并让界面文案反映实际行为。
- [ ] 在 `tests/game-state.test.mjs` 覆盖并发点击、槽满后三连结算、撤回暂存顶牌、洗牌保持类型计数、失败后重开、旧回调在新局到达、空棋盘但暂存未清空。浏览器补测触摸、鼠标和键盘各触发一次。

### P2 · 原创界面与交付验收

- [ ] 为网页版设计独立的主题、图标、牌面、槽位和声音。先用可交互原型验证棋盘与操作区的主次关系，再使用原创或授权素材完善。将可选牌、遮挡牌、最后一个空槽、无可用道具以及结算状态做出明确区分。
- [ ] 暂存区有牌时展示可操作顶牌。道具标识绑定真实的剩余次数和可用状态。为键盘操作、焦点样式、音效开关和减少动态效果提供一致反馈。
- [ ] 发布前在本地静态服务完成双关卡通关、失败重试、刷新加载和移动视口回归。检查浏览器控制台、资源 404、音效用户手势及离线时的基础运行。保存各尺寸开局和结算截图，附上提交号与测试记录。
